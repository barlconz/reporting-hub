SEFK integrated project plan — how it works

This page describes the SEFK integrated project plan Gantt: where the data comes from, what each row and bar means, and how to read the colours and controls.

Live report: Open the integrated project plan Gantt · GitHub Pages mirror

What this report shows

A single timeline of the SEFK programme schedule from Jira, organised as four nested layers:

  1. Phase — top-level programme phase (e.g. Phase 1)
  2. Sub-Phase — major delivery blocks within a phase (e.g. Mobilisation, Architecture and Configure)
  3. Work Stream — functional or delivery stream within a sub-phase (e.g. data migration, HCM)
  4. Epic — schedulable epic rows under each work stream

Each row has a label on the left and a horizontal bar on the right. The bar spans from the issue’s start date through its due date. Labels also show elapsed, working, and week metrics: (ED … | WD … | W …).

KPMG → SEFK sync

The Gantt does not read KPMG Jira directly. Schedule authority sits in KPMG programme Jira (TWOA on KPMG’s Atlassian site). A one-way sync hub mirrors selected work items into TWoA Jira (SEFK), and this report reads the mirror.

How the schedule hierarchy is built on SEFK

Sync constructs the four Gantt layers in SEFK from KPMG fields and parent links:

  1. Phase — programme container (currently Phase 1)
  2. Sub-Phase — from KPMG Delivery Phase values (e.g. Mobilisation, Architecture and Configure)
  3. Work Stream — from the delivery phase plus KPMG component (e.g. integration, HCM, data migration)
  4. Epic — synced from matching KPMG epics and parented under the correct work stream

Start and due dates on Phase, Sub-Phase, and Work Stream rows are rolled up from their children (earliest start, latest due). Synced leaf work — tasks, actions, deliverables, and similar types — does not appear as Gantt rows but feeds the Story Points roll-up that drives bar colour on epics.

What this means for the report

  • The chart shows the SEFK mirror as of the last sync run and the last GitHub Pages refresh — not KPMG Jira live.
  • Schedule or status changes in KPMG typically appear here after the next incremental sync (usually within 30 minutes) and the next report publish.
  • To inspect the authoritative source, open the synced issue in Jira and follow the KPMG Reference link or the source issue note in the description.

Reading the bars

Rows with scoped child work (Story Points roll-up)

When an epic (or a parent row that inherits child roll-up) has in-scope child issues with Story Points, the bar shows a D-Train composition: coloured segments left-to-right from Drive (late / done) through to Dream (early / not started). Segment width reflects the relative weight of child issues in each D-Train phase.

Drive Deploy Demonstrate Deliver Develop Design Discover Dream

Click a coloured segment to open a Jira search for the contributing issues in that phase. Hover for counts and percentages in the tooltip.

Rows without scoped Story Points

If a schedule row has no in-scope child issues with Story Points, the bar is a solid colour derived from that row’s own Jira status, mapped to a D-Train phase (for example Not Started → Dream, In Progress → Develop, Completed → Drive).

Using the chart

  • ▼ beside sub-phases and work streams — collapse or expand nested rows. Collapsing a sub-phase hides all work streams and epics beneath it; collapsing a work stream hides its epics only.
  • Row labels — link to the Jira issue. Work stream labels show the stream suffix only (e.g. data migration) because the sub-phase name is already on the parent row.
  • Horizontal scroll — when the timeline is wider than the viewport, scroll horizontally (shift + mouse wheel also pans).
  • Today marker — vertical black line at the current date (Pacific/Auckland).
  • Calendar grid — light vertical lines at week start (hover for date); dashed lines at month start (hover for month).

What is not shown

  • Issues outside the smart-project-sefk filter
  • Issues labelled kpmg-deleted (KPMG source removed; tombstoned by sync-hub)
  • Rejected child issues in scope roll-ups
  • Task-level rows (only the four schedule layers above appear as Gantt rows; tasks/actions feed bar colour only)
